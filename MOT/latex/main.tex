\section{Implementation}

The algorithm is implemented in Python, using the Numpy and Scipy packages.

The MOT algorithm is fully contained in the \texttt{MOT} class, 
initiating an instance takes a few arguments:

\begin{itemize}
    \item \texttt{curve} is a \texttt{numpy} array of shape \((2, N_S+1)\). 
    The first index is the coordinate 
    (\texttt{0} for \(x\) or \texttt{1} for \(y\), generally \texttt{\_x} and \texttt{\_y} were written as aliases for 0 and 1).
    \(N_S\) is the number of segments in which the curve has been discretized. 
    This field consists out of the edges of these segments (the first and last elements must equal),
    \item \texttt{dt} is the time step in seconds,
    \item \texttt{N\_T} is the number of timesteps taken, and
    \item \texttt{N\_G} is the number of points for the Gaussian quadrature.
\end{itemize}

With these arguments the quadrature points (\texttt{coordquad} and \texttt{weights}),
the geometry fields (\texttt{rho} are the midpoints, \texttt{tangents} the tangent vectors and \texttt{l} the lengths of the segments, \texttt{rhop[\_x, m, g]} is the \(x\)-coordinate of the \(m\)-th segment, linearly interpolated for \(x_g\)),
\(F\) (an array of shape \((N_T, N_S, N_S, N_G)\), such that \(F(k,\rho_m,\rho_{n,g}) = \texttt{F[k,m,n,g]}\)) 
and \(Z\) (with shape \((N_T, N_S, N_S)\), so that \((Z_k)_{m,n} = \texttt{Z[k,m,n]}\))
are calculated.

Finally the function \texttt{solve} implements the stepping algorithm.
It takes one argument \texttt{V}, which is an array of shape \((N_T, N_S)\), 
such that \((V_j)_m = E^i(\rho_m, j \Delta t) = \texttt{V[j,m]}\).
The solver (and \texttt{\_init\_Z}) uses the Numpy function \texttt{einsum}, 
which makes translating sums from math into code a lot easier: 
\[ \sum_{g}^{N_G} w_g F(k, \rho_m, \rho_{n,g}) = \texttt{np.einsum('g,kmng->kmn', weights, F)} \]

This and a few reshapes which had to happen for Numpy to be able to correctly broadcast together some arrays,
are the only noteworthy difference between the code and its mathematic description from the assignment.

The spectrum of the incoming wave quickly decays to zero. 
This means that when dividing by this spectrum the result will explode.
Due to this the frequency range for which the solver can be used is only limited.
We chose to limit the frequency range to the region where the spectrum of the incoming wave is more than 0.1 \% of its maximum.

When calculating the Fourier transform of the solution from the MOT-algorithm, 
Numpy's \texttt{rfft} function was used. 
It is important to note that this is a discrete transform without any normalization factor.
To compare it with the continuous transform, a correction factor of \(dt/\sqrt{2 \pi}\) is needed.

\subsection{Analytical Solution}

\begin{equation}\label{eq:analytical-ez}
    e_z(\vec{\rho}) = \sum_{n=-\infty}^{\infty} j^n \left( J_n(k\rho) - \frac{J_n(ka)}{H_n^{(2)}(ka)} H_n^{(2)}(k\rho) \right) e^{j n \phi}
\end{equation}

The analytical solution (\ref{eq:analytical-ez}) for \(e_z\) is copied from appendix B from the assignment.
The derivate towards \(\rho\) is taken and evaluated at \(\rho = a\):
\[ \sum_{n=-\infty}^{\infty} j^n \left( k J_n'(k a) - k \frac{J_n(ka)}{H_n^{(2)}(ka)} H_n'^{(2)}(k a) \right) e^{j n \phi}. \]
With a bit of refactoring, 
\[ \sum_{n=-\infty}^{\infty} \frac{j^n k}{H_n^{(2)}(ka)} \left( J_n'(k a) H_n^{(2)}(ka) - J_n(ka) H_n'^{(2)}(k a) \right) e^{j n \phi}, \]
the Wronskian relationship is revealed,
so that finally equation \ref{eq:analytical-jz} follows.

\begin{equation}\label{eq:analytical-jz}
    j_z = \frac{1}{j \omega \mu} \sum_{n=-\infty}^{\infty} \frac{j^n k}{H_n^{(2)}(ka)} \frac{2 j}{\pi k a} e^{j n \phi}
\end{equation}

The summation in this equation was cut off at \(k a + 2 \approx N \in Z\),
which was established by the rule of thumb that \(H_n^{(2)}(z)\) decays exponentially
as soon as \(n > z\) in combination with some experimentation.

The width of the incoming pulse can be made smaller,
so that in the frequency domain it becomes wider.
This cannot be continued indefinitely, 
as the timestep \(dt\) becomes too small to represent the pulse correctly in the timedomain.
Making \(dt\) smaller makes that the pulse more correctly approximates a Gaussian pulse,
but also makes the maximum frequency (after the Fourier-transform) bigger.
At these maximum frequencies the spectrum of the incoming pulse is again nearly zero,
so that the additional range in frequencies gained is useless.
Thus a tradeoff between the width of the pulse and the timestep must be made.
Another parameter that can be adjusted is \(t_{end}\). 
As this increases the resolution in the frequency domain also increases,
so that finer details are visible.
Increasing this (or decreasing \(dt\)) comes at a computational cost,
as these increase the total steps in time \(N_T\), 
so that the computation takes longer.
Increasing the radius of the PEC increases the difference between the current at the shadow-side
and at the `sun'-side.
The same effect can also be accomplished by decreasing the width of the incoming pulse.

Lastly \(N_S\) and \(N_G\) can be changed.
The number of segments must be great enough so that the geometry of the PEC is correctly approximated.
Increasing this any further does not increase the accuracy very much.
Increasing \(N_S\) also comes at the cost of requiring more memory.
The order of the Gaussian quadrature does not have much influence.
As, once the geometry is well approximated, \(\rho_m\) are close toghether,
so that \(|\rho_m - \rho'|\) in \(F\) is small and can easily be approximated by a low order polynomial.
